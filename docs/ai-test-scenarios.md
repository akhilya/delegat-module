# AI Assistant — Test Scenarios

Документ для анализа качества AI-ассистента и обнаружения регрессий в поведении.

**Формат каждого сценария:**
- **Страница** — где открыт UI при тестировании
- **Запрос** — точный текст пользователя
- **Ожидаемое** — что AI должен сделать
- **Антипаттерн** — что AI НЕ должен делать (считается багом)
- **Проверка** — как убедиться что всё верно

---

## 1. Context-aware операции

Сценарии где `pageContext` должен устранить необходимость в уточнениях.

### С-01: Улучшить описание текущего товара

**Страница:** `productEditPage` (открыт товар "Nike Air Max 90", id=55)
**Запрос:** `"улучши описание товара"`
**Ожидаемое:**
1. AI вызывает `get_product(id=55)` — берёт productId из контекста
2. Предлагает план: обновить описание товара 55
3. После подтверждения вызывает `update_product(id=55, description="...")`

**Антипаттерн:** AI спрашивает "Какой товар вы имеете в виду?" или "Укажите ID товара"
**Проверка:** Описание обновляется без уточняющих вопросов; ID в вызове совпадает с открытым товаром

---

### С-02: Цена текущего товара

**Страница:** `productEditPage` (товар id=55)
**Запрос:** `"поставь цену 2990"`
**Ожидаемое:**
1. propose_plan: обновить цену товара 55 → 2990
2. После подтверждения: `update_product(id=55, price=2990)`

**Антипаттерн:** Спрашивает ID товара или "уточните какой товар"
**Проверка:** Один вызов инструмента с правильным productId

---

### С-03: Заполнить незаполненные поля маппинга

**Страница:** `fieldMappingPage` (маппинг id=103, Wildberries)
**Запрос:** `"заполни незаполненные поля маппинга"`
**Ожидаемое:**
1. AI вызывает `generate_mapping_suggestions(id=103)` — берёт mappingId из контекста
2. Возвращает результат с количеством заполненных полей

**Антипаттерн:** "Укажите ID маппинга" или "Какой маппинг вы имеете в виду?"
**Проверка:** Вызов с id=103; поля обновляются в редакторе (авто-обновление через mappingRefreshToken)

---

### С-04: Удалить все статические значения текущего маппинга

**Страница:** `fieldMappingPage` (маппинг id=103)
**Запрос:** `"удали все статические значения"`
**Ожидаемое:**
1. `get_mapping(id=103)` — получить список полей
2. Найти все поля с sourceType="static"
3. propose_plan: удалить N статических значений (перечислить поля)
4. После подтверждения: `remove_field_connection` для каждого поля

**Антипаттерн:**
- "К какому полю относится это значение?" → баг: mappingId уже известен
- "К сожалению, я не могу увидеть список статических значений" → баг: `get_mapping` даёт полные данные
- Вызов `list_external_categories` → нерелевантный инструмент
- Двойное `propose_plan` → баг подтверждения

**Проверка:** Ровно один `propose_plan`, ровно один блок подтверждения; маппинг обновляется без перезагрузки страницы

---

### С-05: Экспортировать товары текущего подключения

**Страница:** `connectionPage` (подключение "Ozon", id=3)
**Запрос:** `"запусти экспорт товаров"`
**Ожидаемое:**
1. propose_plan: экспорт всех товаров на подключение Ozon (id=3)
2. После подтверждения: `export_products_batch(connectionId=3)`

**Антипаттерн:** "Укажите подключение" или "Какой маркетплейс?"
**Проверка:** connectionId=3 в вызове

### С-10: Изменить цены в категории

**Страница:** любая
**Запрос:** `"увеличь цену всем товарам категории Обувь на 500 рублей"`
**Ожидаемое:**
1. `list_categories()` — найти категорию Обувь
2. `get_products_count(categoryId=X)` — узнать сколько товаров
3. propose_plan: +500 у N товаров
4. `update_product_prices(categoryId=X, amount=500, mode="add")`

**Антипаттерн:** Спрашивает ID категории; не собирает count перед планом
**Проверка:** plan.affectedCount совпадает с реальным числом товаров в категории

**Проверка:** Вопрос содержит список конкретных подключений

## 4. Маппинг-операции

### С-14: Подключить поле по имени

**Страница:** `fieldMappingPage` (маппинг id=103)
**Запрос:** `"подключи поле Цвет к атрибуту Цвет категории"`
**Ожидаемое:**
1. `get_available_sources(id=103)` — найти attributeId для атрибута "Цвет"
2. `get_external_fields(...)` — найти adapterFieldKey для поля "Цвет"
3. propose_plan: connect_field
4. `connect_field(mappingId=103, adapterFieldKey="...", sourceType="attribute", sourceAttributeId=X)`

**Антипаттерн:** Просит пользователя указать ключ поля вручную
**Проверка:** Поле соединено; маппинг обновляется без перезагрузки

---

### С-15: Предпросмотр маппинга

**Страница:** `fieldMappingPage` (маппинг id=103)
**Запрос:** `"покажи как будет выглядеть маппинг для товара Кроссовки Nike"`
**Ожидаемое:**
1. `list_products(search="Кроссовки Nike", pageSize=1)` — найти productId
2. `preview_mapping_for_product(mappingId=103, productId=X)`
3. Таблица с результатами

**Антипаттерн:** Спрашивает ID маппинга или ID товара
**Проверка:** Таблица fieldKey → значение по каждому полю

---

### С-16: Добавить модификатор усечения

**Страница:** `fieldMappingPage` (маппинг id=103)
**Запрос:** `"добавь усечение до 255 символов для поля описания"`
**Ожидаемое:**
1. `get_external_fields(...)` или `get_mapping(id=103)` — найти ключ поля описания
2. propose_plan: add_field_modifier
3. `add_field_modifier(mappingId=103, adapterFieldKey="description", modifierType="truncate", params={length:255})`

**Антипаттерн:** "Укажите adapterFieldKey"
**Проверка:** Модификатор появился; маппинг обновлён

## 5. Bulk-операции

### С-17: Массовое обновление атрибута

**Страница:** любая
**Запрос:** `"поставь атрибут Сезон = Лето всем товарам в категории Обувь"`
**Ожидаемое:**
1. `list_categories()` — найти ID Обуви
2. `list_category_fields(id=X)` — найти key атрибута "Сезон"
3. `get_products_count(categoryId=X)` — сколько товаров
4. propose_plan с affectedCount
5. `update_product_attribute(attributeKey="season", value="Лето")` — без productIds (весь раздел)

**Антипаттерн:** Спрашивает "для каких товаров?"; не собирает count
**Проверка:** affectedCount в плане ≠ 1; изменение применено к нескольким товарам

---

### С-18: Умножить цены на коэффициент

**Страница:** любая
**Запрос:** `"умножь цену всех товаров на 1.1"`
**Ожидаемое:**
1. `get_products_count()` — всего товаров
2. propose_plan с isDestructive=true и affectedCount = все товары
3. `update_product_prices(amount=1.1, mode="multiply")`

**Антипаттерн:** Не предупреждает что затронет ВСЕ товары
**Проверка:** plan.isDestructive=true; plan.affectedCount = реальное число товаров

---

## 6. Подтверждение и откат

### С-19: Одно подтверждение — одно выполнение

**Страница:** любая
**Запрос:** `"создай категорию Аксессуары 2025"`
**Ожидаемое:**
1. propose_plan (один раз)
2. Пользователь нажимает "Выполнить"
3. AI выполняет `create_category(name="Аксессуары 2025")` без повторного propose_plan

**Антипаттерн:** После "Выполнить" AI показывает второй propose_plan и снова просит подтверждения
**Проверка:** Ровно один блок "Вот что я собираюсь сделать" в диалоге

---

### С-20: Откат последней операции

**Страница:** любая (после мутации из С-19)
**Запрос:** `"отмени"`
**Ожидаемое:** `rollback_last_operation()` → категория удалена, сообщение об успехе

**Антипаттерн:** Уточняет "что именно отменить?"; не выполняет откат
**Проверка:** Категория исчезла из `list_categories()`

---

### С-21: Отмена плана

**Страница:** любая
**Запрос:** `"удали все товары"`
**Ожидаемое:**
1. propose_plan с isDestructive=true
2. Пользователь нажимает "Отмена"
3. AI подтверждает отмену ("Операция отменена. Что изменить?")

**Антипаттерн:** AI выполняет удаление до нажатия "Выполнить"
**Проверка:** Товары не удалены; в диалоге нет вызова delete_products

---

## 7. Регрессии

Сценарии для обнаружения конкретных известных багов.

### Р-01: Двойной propose_plan (баг из реального диалога)

**Страница:** `fieldMappingPage` (маппинг id=103)
**Запрос:**
1. `"удали все статические значения"` → AI показывает план → нажать "Выполнить"
2. AI должен выполнить, не спрашивая снова

**Ожидаемое:** После нажатия "Выполнить" AI сразу запускает инструменты
**Антипаттерн:** Второй блок "Вот что я собираюсь сделать:" после нажатия кнопки
**Проверка:** В диалоге ровно один plan-block; инструменты запускаются без повторного подтверждения

---

### Р-02: Нерелевантный инструмент (list_external_categories при удалении полей)

**Страница:** `fieldMappingPage`
**Запрос:** `"удали все статические значения"`
**Ожидаемое:** AI вызывает только `get_mapping`, `remove_field_connection` (и возможно `get_mapping_coverage`)
**Антипаттерн:** Вызов `list_external_categories` — полностью нерелевантен для этой задачи
**Проверка:** В списке tool badges нет `list_external_categories`

---

### Р-03: Отсутствие реактивности маппинга

**Страница:** `fieldMappingPage` (граф видно в UI)
**Запрос:** `"удали статическое значение поля Бренд"`
**Ожидаемое:** После выполнения граф-редактор автоматически обновляется (блок "Бренд = Adidas" пропадает)
**Антипаттерн:** Значение осталось на экране до ручного обновления страницы
**Проверка:** Изменение видно в редакторе без F5

---

### Р-04: Множественные вопросы в одном ответе

**Страница:** любая
**Запрос:** `"создай маппинг"` (без деталей)
**Ожидаемое:** AI задаёт ровно ОДИН вопрос (например "Для какого подключения?")
**Антипаттерн:** "Мне нужно знать: 1) подключение 2) локальная категория 3) внешняя категория..."
**Проверка:** В ответе одно предложение-вопрос

---

### Р-05: Контекст страницы не используется

**Страница:** `fieldMappingPage` (маппинг id=103)
**Запрос:** `"сколько полей не заполнено?"`
**Ожидаемое:** `get_mapping_coverage(id=103)` с id из контекста страницы
**Антипаттерн:** "Укажите ID маппинга"
**Проверка:** ID в вызове = 103

## Метрики качества

| Метрика | Хорошо | Плохо |
|---------|--------|-------|
| Уточняющие вопросы при наличии pageContext | 0 | > 0 |
| propose_plan на одну операцию | 1 | > 1 |
| Нерелевантные инструменты | 0 | > 0 |
| Инструментов для достижения цели | ≤ 3 | > 5 |
| Обновление UI после мутации маппинга | автоматически | требует F5 |
| Вопросов на один ответ | ≤ 1 | > 1 |
