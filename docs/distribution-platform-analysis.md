# Анализ инфраструктуры дистрибуции PrintO Dashboard

> Этот документ описывает инфраструктуру дистрибуции платформы — провижининг, обновления, лицензирование, центральную панель и биллинг. Это **отдельный проект** от самой платформы.
>
> Анализ качества самой платформы: [multi-seller-analysis.md](./multi-seller-analysis.md)

---

## 1. Автоматический провижининг инстансов

- **Текущее состояние:** Ручной деплой через Dokploy webhook.
- **Нужно:** API/скрипт для создания нового инстанса:
  - Генерация docker-compose из шаблона с уникальными credentials
  - Создание DNS записи (*.printo.studio -> поддомен)
  - Запуск контейнеров
  - Ожидание health check
  - Создание первого admin-пользователя (через ADMIN_SEED env vars — уже поддерживается)
- **Варианты реализации:** Dokploy API, Coolify, custom orchestrator, Kubernetes

---

## 2. Система обновлений

- **Текущее состояние:** Push в master -> CI build -> один Dokploy webhook (один инстанс).
- **Нужно:** Механизм обновления всех инстансов:
  - Версионирование Docker images (registry)
  - Rolling update всех инстансов (по одному или группами)
  - Миграции БД уже авто-применяются при старте — это плюс
  - Data migrations тоже авто-применяются — это плюс
  - Rollback стратегия при ошибке миграции
- **Варианты реализации:** Docker Hub/GHCR + Watchtower, Dokploy per-project, K8s

---

## 3. Лицензирование / активация

- **Текущее состояние:** Никакой защиты, код открыт.
- **Нужно:**
  - License key проверка при старте (или периодически)
  - Привязка к домену/поддомену
  - Центральный license сервер (или offline keys с подписью)
  - Graceful degradation при истечении лицензии (read-only режим или баннер)
- **Реализация:** Middleware в Program.cs, проверка license key из env var

---

## 4. Центральная панель управления (Admin Portal)

- **Текущее состояние:** Нет.
- **Нужно (отдельное приложение):**
  - Список всех инстансов с их статусом
  - Создание/удаление инстансов
  - Мониторинг: health, версия, использование ресурсов
  - Управление лицензиями/подписками
  - Trigger обновления конкретного инстанса

---

## 5. Биллинг и подписки

- Может быть реализован в центральной панели, а не в каждом инстансе
- Тарифные планы, оплата (ЮKassa для РФ рынка), триалы
- Лицензия привязана к тарифу (ограничения на количество товаров, подключений и т.д.)
